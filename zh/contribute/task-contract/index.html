一个任务包里有什么

以北海沿岸的 72 小时风暴潮预报为例，从 Agent 读到的题文，一直看到评分器写出的结果。每处编号都对应一段 Harbor 题包示例和一条填写说明，可以对照着准备自己的题目。

01 / 05声明运行配置与 AFE 元信息。

task.toml

示例

1schema_version · artifacts

schema_version = "1.4"
artifacts = ["/work/output"]
1

把预报文件交给评分器

这两项写在文件开头。Agent 结束后，Harbor 收集 /work/output，并在评分环境中还原到相同的绝对路径。

2[task]

name = "afe/north-sea-storm-surge"
version = "0.1.0"
description = "72-hour North Sea storm-surge forecasts"
authors = [{ name = "Example coastal research team" }]
2

标明题目、版本和署名

在 afe/ 后填写英文短名称，用一句话说明科研目标，并列出作者或团队。修订题包时更新题目版本。

3[metadata.afe]

protocol_version = "1.0"
level = "L1"
domains = ["地球"]
supports_over_target = false
3

说明等级与领域

本轮征集有明确目标和验收条件的 L1 科研题。领域取自模板，可多选。题目有明确的超目标判据时，才启用超目标标记。

4[metadata.afe.score_mapping]

url = "tests/score.py"
description = "50 points per region with lower RMSE than the reference."
4

说明每一档分数的科学含义

本例有两个海区。一处预报误差低于固定对照得 50 分，两处都改善才得 100 分。正式出题时要论证目标和所有必要条件，并指明执行该判定的代码位置。

02 / 05Agent 实际读取的科研题文、交付要求和验收标准。

instruction.md

示例

1## 预报目标

为北海沿岸 24 个验潮站预报未来 72 小时逐小时的风暴增水。能否在北部和南部两个海区都取得低于对照预报的均方根误差（RMSE）？

1

把研究问题写成可验证的目标

明确研究对象、预报时长、比较对象和适用范围。正式科研题还要引用已有工作，说明缺口在哪里，以及达标后能带来什么新贡献。

2## 可用数据与资源

从 /work/input/ 读取站点与海区编号、历史风暴增水（厘米）、风场与气压预报。只使用起报时已知的信息。可在离线环境中使用两核 CPU 和 4 GiB 内存，限时一小时。

2

界定 Agent 可以使用的信息

写明路径、单位、数据截止时间和可用工具。本例只在交付后评分。若允许中途验证，还要写明调用命令、返回的反馈和查询次数限制。

3## 最终交付

/work/output/forecast.csv

station_id,window_id,lead_hour,surge_cm
N01,W001,1,12.5
N01,W001,2,13.1
3

给出评分器能直接读取的产物样例

每个站点、窗口和预报时效（1–72 小时）的组合恰好一行，增水值为有限数，单位厘米。本例将漏行或重复行判为无效提交。评分代码读取同一路径，并按这四列解析。

03 / 05构建解题环境，提供 Agent 可以访问的数据和工具。

environment/

示例

1input/

stations.csv
historical_surge.csv
weather_forecasts.csv
forecast_windows.csv
1

准备解题时可见的输入

四份文件分别给出 24 个站点及其分区、历史观测、气象预报和起报窗口。外部数据应说明单位和获取条件。随包提供的解题工具可放在 tools/。

2Dockerfile

FROM python:3.11.11-slim-bookworm
WORKDIR /work
COPY input/ /work/input/
RUN mkdir -p /work/output
2

让题文里的路径在容器中真实存在

COPY 将输入文件放到题文约定的 /work/input/。额外软件和工具也在这里安装或复制。用于验收的风暴增水观测保存在独立评分镜像中。

04 / 05构建独立评分环境，用提交产物验证科研目标。

tests/

示例

1Dockerfile

FROM python:3.11.11-slim-bookworm
WORKDIR /tests
COPY . /tests/
RUN chmod +x /tests/test.sh
1

把最终验收所需的材料放进评分环境

随包放入 score.py、留出的观测和按相同窗口与输入条件生成的对照预报。先按站点、窗口、时效对齐预报与观测，再比较误差。

2test.sh

#!/bin/sh
set -eu
mkdir -p /logs/verifier
python3 /tests/score.py
2

通过 Harbor 的固定入口评分

Harbor 调用 tests/test.sh。本例的 score.py 读取 /work/output/forecast.csv，检查行与字段，再分海区算 RMSE。每个海区的 RMSE 严格低于对照得 50 分。

3/logs/verifier/afe_result.json

{
  "status": "evaluated",
  "score": 50,
  "raw": {"regions_improved": 1, "regions_total": 2}
}
3

记录科研主分及其依据

这份输出表示两个海区中有一个得到改善。必须写 status 和 score，可在 raw 中保留原始指标及其单位。已评价结果为 0–100 分。若题目支持、结果也确实超过目标，可在 100 分时标记 target_exceeded。

4/logs/verifier/reward.json

{"reward": 0}
4

记录是否达成完整目标

上例得 50 分，reward 为 0。已评价且得 100 分时 reward 为 1。无效提交（invalid_submission）主分与 reward 都为 0，并附错误说明。评分出错（evaluation_error）或等待人工复核（pending_review）时，主分为 null，省略 reward 文件。

说明参考方法的来源

提供参考方法时，记录名称、提出时间、原理和来源。这里引用介绍 GTSM v3.0 的论文。只有在本题条件下实际测过，才填写该方法的原始指标或主分。

2task.toml → [metadata.afe]

reference_urls = ["solution/gtsm/info.json"]
2

在配置中登记参考方法

在 reference_urls 中列出各方法的目录或 info.json 路径。没有参考解的开放题可以省略 solution/。验收科学主张所必需的对照数据仍要放在 tests/。
