任务合同

一个任务包里有什么

每个被收录的任务都以一个包含五部分的文件夹保存。下面是一个仅供参考的沿海风暴潮预报任务的示意任务包：左侧展示每个部分里放什么，右侧编号说明对应字段有什么用、应该怎么填。

task_id/

  1. instruction.json
  2. input/
  3. environment/
  4. verifier/
  5. meta.json

01 / 05

instruction.json

示例

1instructions

  • 你需要为北海沿岸 24 个验潮站预报未来 72 小时内的风暴潮。公开输入位于 /input/data：2000–2019 年逐小时水位、对应的大气再分析子集、站点元数据和 120 个预报窗口。
  • 最多可以请求 5 次 validation，每次在 20 个公开窗口上评分。完成 results/forecast.csv 与 report/report.md 后，发送一次 test 作为最终提交。
1

任务说明

说清楚任务背景、任务目标、数据的概况和输出的要求。如果有单独的 validation 设置或对 validation 有特殊要求，也可以在此提出；任务也可以只有 test 部分。

2input

  • data/water_levels_2000_2019.nc · NetCDF — 24 个站点的逐小时水位
  • data/era5_forcing.nc · NetCDF — 大气再分析子集
  • data/stations.csv · CSV — 站点坐标与基准面
  • data/forecast_windows.json · JSON — 120 个预报窗口
2

声明 Agent 可以看到的输入

每一项给出 input/ 下的路径、格式和简单的内容描述。

3submission

  • results/forecast.csv · CSV · 有模板 — 每个站点 × 窗口 × 预报时效一行，预测风暴潮高度（cm）。主分数由此文件计算。
  • report/report.md · Markdown · 有模板 — 方法、验证策略与已知失效情形。
3

逐个列出要提交的文件

路径、格式、是否有模板。如果有模板，模板会放在 input/ 目录下的相同相对路径。

4environment

  • python 3.12 · xarray 2025.6
  • netCDF4 1.7 · scikit-learn 1.7
4

默认镜像之外的软件

这里的内容仅供被测 AI 了解环境中有哪些工具。实际的工具安装需要在 environment/ 中配置好完备的构建文件。

5requirement

  • 不得下载或查询这些站点 2019 年之后的水位观测。在线检索方法、论文与软件是允许的。
5

额外的规则说明

用来配置额外的要求，如特定的数据不应该被检索。默认设置是联网的，所以可以在此设置专门禁止访问的数据源。实验室会有专门的过程审查流程，检测被测 AI 是否违反 requirement。可置空。

6limitation

8 核 CPU · 32 GB 内存 · 1 块 GPU · 12 小时运行时间

6

资源限制

任务需要的资源；任务上线前由 SIE 团队确认最终值。

02 / 05

input/

示例

1data/

  • water_levels_2000_2019.nc
  • era5_forcing.nc
  • stations.csv
  • forecast_windows.json
  • README.md
1

科学输入

与 instruction.input 中声明的每一项一一对应。附一份简短的 README 说明列名、单位与缺测，方便 Agent 正确读取。

2results/ · report/

  • results/forecast.csv（模板）
  • report/report.md（模板）
2

提交模板

提供给被测 AI 的模板，对于部分产物也可无需准备模板。verifier 中读取的路径要和这里的路径保持一致。

03 / 05

environment/

示例

1environment.json

  • schema_version: 1.0
  • type: containerfile
1

两种选择

type: default 使用运营方默认镜像，不添加任何内容；type: containerfile 则用本目录中的 Containerfile 构建任务镜像。

查看默认镜像包含的内容 ↗

2Containerfile

  • FROM <运营方默认镜像>
  • RUN pip install xarray==2025.6 netCDF4==1.7 scikit-learn==1.7
2

从默认镜像出发，固定版本

只添加任务需要的软件并写明精确版本。构建必须可复现，不能在运行时下载数据或模型权重。

04 / 05

verifier/

示例

1validation/

  • run/main.py
1

运行阶段的可选验证

运行阶段被测 AI 可以选择性调用的验证方式。可选，且与 test 模块的逻辑完全一致。除需要提供 run/main.py 供框架调用之外，其余内容不做要求。

2test/

  • run/main.py
  • data/hidden_observations_2020_2024.nc
2

最终评分

最终的结果评测模块，模型调用之后评测立即结束。同样只要求提供 run/main.py。validation 和 test 所需的数据都需要自包含，不能放在目录之外。

05 / 05

meta.json

示例

1id · title · domain

  • storm_surge_forecast_72h
  • 沿海风暴潮 72 小时预报
  • earth science
1

任务身份

id 同时是文件夹名与榜单键，发布后不再变。domain 使用站点统一的领域列表。

2task_sources

  • GESLA-3 验潮站档案
  • ERA5 再分析（Copernicus Climate Data Store）
2

任务的来源

任务原型的来源 URL（论文、基准或项目页面），如有也包括所用数据的 URL。名称加可解析的 URL 或 DOI。

3metric.description

所有隐藏窗口上预测与观测风暴潮的 RMSE（cm），越低越好。无效提交不参与排名。

3

指标语义

方向、单位、聚合方式，以及无效输出如何处理。这段文字会在任务页原样展示给读者。

4metric.type

linear_minimize

4

指标类型

原始分的方向与形态，如 linear_minimize、linear_maximize。用来将原始分数统一为方便理解的标准分数。部分类型可能需要额外给定参数。

5baseline

  • existing_baseline: true
  • name: 持续性 + 调和潮
  • source: https://example.org/storm-surge/baseline/
  • score: 18.4
  • bottom_line_score: 30.0
5

基线

已存在的参考方法，必须提供。如没有，也须提供合理的分数，此时可不填写 source 字段并将 existing_baseline 置为 false。bottom_line_score 为题目构建者给出的合理低分，在标准分数中会被映射为 0 分。
