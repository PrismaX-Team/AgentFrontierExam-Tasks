共建政策

01

共同作者

至少有 1 个任务包通过审核并被采纳的贡献者，可成为项目论文共同作者；需配合完成任务核验、内容修订和作者信息确认。

02

审核者与核心维护者

被采纳任务包超过 4 个的成员，有机会受邀担任 reviewer，并进入核心维护者团队。

审核流程

  1. 01

    提交 Proposal

    在 GitHub Discussions 中说明：科学问题为什么重要、Agent 要产出什么、如何评分，以及数据与软件的许可。

  2. 02

    Proposal 审核

    一位领域专家对照四项任务特性审核。意见公开在讨论串中；必要时请你修订后再审。

  3. 03

    提交 PR

    获批后复制模板整理五部分任务包（可用 Skill 让 AI 协助），从你的 fork 提交引用该 Proposal 的 PR。CI 自动检查目录结构与必填字段。

  4. 04

    PR 审核

    一位领域专家核对科学内容与指标语义，一位技术专家核对实现、环境与 verifier 的确定性。两位都批准后合并。

  5. 05

    收录

    任务进入 Agent Frontier Exam 任务集并公开，你署名为贡献者。后续修复在同一仓库以 PR 跟进。

任务特性

01

科学重要性

结果变好后，应能推进真实研究问题或重要科学计算瓶颈。

02

Verifier 可信度

评分算法、输入、常数、容差、聚合和无效输出处理能够完整固定，并在本地、离线、确定性运行。

03

前沿空间

当前最佳可达结果仍未知，并有可信证据表明存在实质改进空间。

04

长期可持续性

数据、软件和验证路径能够稳定获得，不依赖脆弱服务、秘密凭证或不可重复的外部行为。

查看详情→

task_id/

  1. instruction.json

    面向 Agent 的任务说明、输入声明、提交产物、已提供环境、额外要求与运行上限。

  2. input/

    只包含 Agent 可见的科学输入与提交模板。

  3. environment/

    environment.json 选择运营方默认镜像或任务专用 Containerfile。

  4. verifier/

    两个固定程序，各有一个入口。

    1. validation/

      Agent 在研究过程中可请求的反馈；可没有。

    2. test/

      提交冻结后的一次最终评分；离线、确定性。

  5. meta.json

    任务身份、数据来源、指标语义与公开分数映射。
