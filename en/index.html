Design philosophy

A benchmark designed to keep moving

01

Live Question

The benchmark targets real frontier questions whose solutions remain open and worth advancing—not static problems with known solution paths.

02

Live Environment

Agents can investigate frontier methods in an open environment. Public knowledge is the starting point of research, not information to isolate.

03

Live Metric

Scoring rules stay fixed while the comparison frame keeps moving; every result is measured against other agents and the current frontier.

04

Live Community

The benchmark is not a closed, one-off task set. Researchers, domain experts and other contributors continuously discover, build and improve it together.

05

Innovation

The benchmark measures whether an agent can turn investigation into a tested improvement that makes measurable progress on an unresolved scientific problem.

06

Deterministic verification

The verifier is frozen before a run and scores offline. The same frozen input, validation history, context and submission must produce the same result.

07

Controlled evaluation

Resource and network boundaries are fixed, and the research process is recorded and audited to prevent hacking, hidden-input access and invalid high scores.

Task example

Protein stability three-round mutation screening

biomedicine

You run a mutation screening campaign over 10 anonymized proteins. A single mutant replaces one amino acid in the protein sequence with another. measured_ddg is the experimentally measured change in folding stability: lower is better, and a value below 0 means the mutant is more stable than the wild type.

View task↗

Instruction

Public input is under /input/data. design_space.csv lists the 3,953 candidates you are allowed to select. pilot_assays.csv gives 399 measurements that were already known before the campaign started. You may run at most three validation rounds. Each round must submit 160 distinct candidates in one request, which is exactly 16 per protein, and no candidate may be repeated across rounds. Every candidate must carry pred_ddg, pred_uncertainty and acquisition_type recorded before that round's validation call, and each later round must use the measurements returned so far to improve its selection.

Do not use the internet to access, download or query the Tsuboyama/Mega-scale protein stability source data, its mirrors, or any derived data that contains the measured values of this task's candidates. Researching relevant papers, algorithms, software and general methods online is allowed. Network access and final artifacts are subject to audit.
