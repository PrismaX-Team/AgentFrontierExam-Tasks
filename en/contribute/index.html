Contribution policy

01

Co-authorship

Contributors of at least one accepted task package can be listed as co-authors on the project paper. They must help complete verification, revisions and author-information confirmation.

02

Reviewer and core maintainer path

Members with more than four accepted task packages may be invited to review tasks and join the core maintainer team.

Review process

  1. 01

    Submit a proposal

    Open a GitHub Discussion: why the question matters, what the agent must produce, how it is scored, and the licence of the data and software.

  2. 02

    Proposal review

    One domain expert checks the proposal against the four task properties. Comments are public; you may be asked to revise before it is reviewed again.

  3. 03

    Open a task PR

    After approval, copy the template, assemble the five-part package (an agent skill can help) and open a PR from your fork citing the proposal. CI checks the layout and required fields.

  4. 04

    PR review

    One domain expert checks the science and metric semantics; one technical expert checks the implementation, environment and verifier determinism. Both must approve.

  5. 05

    Accepted

    The task joins the Agent Frontier Exam task set and is published with you credited as its contributor. Later fixes follow as PRs in the same repository.

AFE task guide

What a Agent Frontier Exam task should look like

Task properties

01

Scientific importance

A better result would advance a real research question or an important scientific computing bottleneck.

02

Verifier credibility

The scoring algorithm, inputs, constants, tolerances, aggregation and invalid-output rules can be fixed and run locally, offline and deterministically.

03

Frontier headroom

The best achievable result remains unknown, with credible evidence of meaningful room for improvement.

04

Long-term sustainability

Data, software and the verification path can remain available without fragile services, secret credentials or irreproducible external behavior.

Task contract

View details→

task_id/

  1. instruction.json

    Agent-facing instructions, declared inputs, submission artifacts, provided environment, extra requirements and run limits.

  2. input/

    Only Agent-visible scientific inputs and the submission templates.

  3. environment/

    environment.json selects the operator default image or a task Containerfile.

  4. verifier/

    Two fixed programs with one entry point each.

    1. validation/

      Feedback the agent may request during research; optional.

    2. test/

      One final scoring pass on the frozen submission; offline and deterministic.

  5. meta.json

    Task identity, data sources, metric semantics and the public-score mapping.
