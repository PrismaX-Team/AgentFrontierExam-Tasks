Harbor task package

Use the Harbor 0.25.0 template in the contributor guide. Each ZIP contains one task. Include supplementary materials alongside the task folder when needed.

AFE_task_package_template_v1.0.1.zip · Download the template at the end of the guide. For agent-assisted authoring or a read-only review, afe-task-2.0.0.zip includes the same template and self-check tools.

task_package/

  1. task.toml
  2. instruction.md
  3. environment/
  4. tests/
  5. solution/

task.toml

Runtime settings and AFE metadata.

[task] and [metadata.afe]
Set the task name (afe/your-task-name), version and authors. Declare the research level, domains, support for exceeding the target, and the location and meaning of the score mapping. The template uses AFE protocol 1.0.
artifacts
List the absolute output paths to collect. For example, if the instructions ask for /work/output/predictions.csv, collect /work/output. The verifier reads the file at the same path.
[environment] and [verifier]
Specify time limits, CPU, memory, storage, GPUs and network access for each environment. Set verifier.environment_mode to separate.

instruction.md

The research question, deliverables and acceptance criteria the agent reads.

Research objective
Explain the gap in existing work, the contribution that would close it, the fixed conditions and what the agent may explore.
Inputs and outputs
Identify the input paths, formats, fields and units. Give the absolute output paths, required fields and any interface the submitted code or model must expose.
Research conditions
Describe available tools, resource limits and success criteria. If you offer intermediate validation, explain how to call it, what feedback it returns and how requests count against the budget.

environment/

Build the agent’s workspace and provide the inputs and tools it may use.

Dockerfile
Install the software needed to solve the task. Copy the required files into the locations named in instruction.md.
input/ and tools/ (optional)
Include the data and tools your task uses. Document access conditions for external data. Keep hidden evaluation data in the scoring environment.

tests/

Build an independent verifier and score the submitted artifacts.

Dockerfile and test.sh
Harbor runs tests/test.sh in the independent scoring environment. Include the dependencies, evaluation materials and checks that establish the scientific result.
/logs/verifier/afe_result.json
Write status and score. Map evaluated results to 0–100. Zero denotes complete failure and 100 means every necessary scientific condition is met. Discrete scores are allowed. Optional raw metrics preserve their original units. A supported target_exceeded result still scores 100.
/logs/verifier/reward.json
Write reward 1 for evaluated with score 100, and 0 for other evaluated results or invalid_submission. An invalid submission has score 0. For evaluation_error or pending_review, use a null score and omit the reward.

solution/

Optional reference methods, one directory per method.

<method>/info.json
Record the method’s name, date, description and sources. Include code or a comparable measured score when available. You can submit an open research challenge without a reference solution.
reference_urls
List the method directories or their info.json files in metadata.afe when you provide references.
