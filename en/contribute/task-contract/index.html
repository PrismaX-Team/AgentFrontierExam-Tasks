Task contract

What one task package contains

Every accepted task is stored as one folder with five parts. Below is an illustrative package, for reference only, for a coastal storm-surge forecasting task. The left column shows what goes into each part; the numbered notes on the right explain what that field is for and how to fill it in.

task_id/

  1. instruction.json
  2. input/
  3. environment/
  4. verifier/
  5. meta.json

01 / 05

instruction.json

example

1instructions

  • You forecast coastal storm surge up to 72 hours ahead for 24 tide-gauge stations along the North Sea coast. Public input is under /input/data: hourly water levels for 2000–2019, a matching subset of atmospheric reanalysis, station metadata and 120 forecast windows.
  • You may request validation at most 5 times; each request scores your forecasts on the 20 public windows. When results/forecast.csv and report/report.md are complete, send one test action as the final submission.
1

The task brief

State the background and goal of the task, an overview of the data, and what the output must look like. If validation has its own setup or special rules, say so here; a task may also have only a test stage.

2input

  • data/water_levels_2000_2019.nc · NetCDF — hourly water levels, 24 stations
  • data/era5_forcing.nc · NetCDF — atmospheric reanalysis subset
  • data/stations.csv · CSV — station coordinates and datum
  • data/forecast_windows.json · JSON — the 120 forecast windows
2

Declare the inputs the agent may see

Each entry gives a path under input/, its format and a short description of the content.

3submission

  • results/forecast.csv · CSV · template — one row per station × window × lead hour; predicted surge in cm. Carries the primary score.
  • report/report.md · Markdown · template — method, validation strategy and known failure cases.
3

List every file to be submitted

Path, format and whether a template exists. Templates are placed under input/ at the same relative path.

4environment

  • python 3.12 · xarray 2025.6
  • netCDF4 1.7 · scikit-learn 1.7
4

Software beyond the default image

This list only tells the agent which tools the environment provides. The actual installation is configured in environment/ with a complete, reproducible build.

5requirement

  • Do not download or query water-level observations after 2019 for these stations. Researching methods, papers and software online is allowed.
5

Extra rules

Additional obligations, such as data sources that must not be retrieved. The run has network access by default, so forbidden sources are named here. The lab runs a process audit to check whether the agent violated a requirement. May be left empty.

6limitation

8 CPU cores · 32 GB memory · 1 GPU · 12 hours runtime

6

Resource limits

What the task needs; the AFE team confirms the final values before the task goes live.

02 / 05

input/

example

1data/

  • water_levels_2000_2019.nc
  • era5_forcing.nc
  • stations.csv
  • forecast_windows.json
  • README.md
1

Scientific inputs

One file per entry declared in instruction.input. A short README with columns, units and gaps helps the agent read the data correctly.

2results/ · report/

  • results/forecast.csv (template)
  • report/report.md (template)
2

Submission templates

Templates handed to the agent under test; some artifacts may not need one. The paths the verifier reads from must match the paths used here.

03 / 05

environment/

example

1environment.json

  • schema_version: 1.0
  • type: containerfile
1

Two choices

type: default runs on the operator default image with nothing added. type: containerfile builds the task image from the Containerfile in this directory.

What the default image contains ↗

2Containerfile

  • FROM <operator default image>
  • RUN pip install xarray==2025.6 netCDF4==1.7 scikit-learn==1.7
2

Start from the default image, pin versions

Add only what the task needs, with exact versions. The build must be reproducible and must not fetch data or model weights at run time.

04 / 05

verifier/

example

1validation/

  • run/main.py
1

Optional validation during the run

A check the agent under test may call at its own discretion while working. Optional, and its logic is identical to the test module. Apart from providing run/main.py for the framework to call, nothing else is prescribed.

2test/

  • run/main.py
  • data/hidden_observations_2020_2024.nc
2

Final scoring

The module that scores the final result; once the model calls it, the evaluation ends immediately. Again only run/main.py is required. All data needed by validation and test must be self-contained inside the directory, never outside it.

05 / 05

meta.json

example

1id · title · domain

  • storm_surge_forecast_72h
  • Coastal storm-surge 72-hour forecast
  • earth science
1

Task identity

The id is the folder name and the leaderboard key; it does not change after publication. Domain uses the site's domain list.

2task_sources

  • GESLA-3 tide-gauge archive
  • ERA5 reanalysis (Copernicus Climate Data Store)
2

Where the task comes from

URLs of the task's prototype (paper, benchmark or project page) and, if any, of the data it uses. Name plus a resolvable URL or DOI.

3metric.description

RMSE in cm between predicted and observed surge over all hidden windows; lower is better. Invalid submissions are not ranked.

3

Metric semantics

Direction, unit, what is aggregated and how invalid outputs are treated. Shown to readers verbatim on the task page.

4metric.type

linear_minimize

4

Metric type

Direction and shape of the raw score, such as linear_minimize or linear_maximize. Used to map raw scores onto a standard score that is easy to read. Some types may need extra parameters.

5baseline

  • existing_baseline: true
  • name: Persistence + harmonic tide
  • source: https://example.org/storm-surge/baseline/
  • score: 18.4
  • bottom_line_score: 30.0
5

Baseline

An existing reference method; required. If none exists, give a reasonable score instead, leave source empty and set existing_baseline to false. bottom_line_score is a reasonable low score given by the task author; in the standard score it maps to 0.
