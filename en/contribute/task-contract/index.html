AFE Research · Harbor 0.25.0

What one task package contains

Follow a 72-hour North Sea storm-surge forecast from the agent’s instructions to the final score. Each numbered excerpt from this illustrative Harbor package is paired with a note on how to write that part of your own task.

01 / 05Runtime settings and AFE metadata.

task.toml

Example

1schema_version · artifacts

schema_version = "1.4"
artifacts = ["/work/output"]
1

Hand the forecast to the verifier

Put these keys at the top of the file. Harbor collects /work/output when the agent finishes and restores it at the same absolute path in the scoring environment.

2[task]

name = "afe/north-sea-storm-surge"
version = "0.1.0"
description = "72-hour North Sea storm-surge forecasts"
authors = [{ name = "Example coastal research team" }]
2

Identify this version of the task

Give the task an English short name under afe/, summarize the research objective and credit the authors. Update the task version when you revise the package.

3[metadata.afe]

protocol_version = "1.0"
level = "L1"
domains = ["地球"]
supports_over_target = false
3

State the research scope

The current call focuses on verifiable L1 research goals. Use the domain names from the template (地球 means Earth science). Enable over-target results only when the task defines how to verify them.

4[metadata.afe.score_mapping]

url = "tests/score.py"
description = "50 points per region with lower RMSE than the reference."
4

Connect the score to a scientific claim

In this example a forecast must improve on the fixed reference in both coastal regions to earn 100. One region earns 50. For your task, justify the target and all necessary conditions, and point to the implementation that checks them.

5Agent and verifier budgets

[agent]
timeout_sec = 3600
[environment]
cpus = 2
memory_mb = 4096
network_mode = "no-network"

[verifier]
environment_mode = "separate"
timeout_sec = 300
[verifier.environment]
cpus = 1
memory_mb = 2048
network_mode = "no-network"
5

Size the two environments separately

The agent has an hour on two CPU cores. The verifier gets five minutes on one core. Set the working directory, storage, GPU and build limits in the template for each environment as well.

02 / 05The research question, deliverables and acceptance criteria the agent reads.

instruction.md

Example

1## Forecast objective

Forecast hourly storm surge over the next 72 hours at 24 North Sea tide gauges. Can you lower the root mean square error (RMSE) relative to the reference forecast in both the northern and southern regions?

1

Tell the agent what it must establish

Name the phenomenon, forecast horizon, comparison and scope. For a research contribution, cite the work that establishes the gap and explain what a successful result would add.

2## Available data and resources

Read the station and region IDs, past surge observations (cm), and wind and pressure forecasts under /work/input/. Use only information available at forecast issue time. You have two CPU cores, 4 GiB of memory and one hour offline.

2

Set the boundary on available evidence

Specify paths, units, data cutoffs and tools. This example uses final scoring only. If agents can request intermediate validation, document the command, feedback and query budget.

3## Final submission

/work/output/forecast.csv

station_id,window_id,lead_hour,surge_cm
N01,W001,1,12.5
N01,W001,2,13.1
3

Show an artifact the verifier can read

One row per station, window and lead hour (1–72), with a finite surge in centimetres. State how missing or duplicate keys are handled. Here either makes the submission invalid. Use the same path and columns in the scoring code.

03 / 05Build the agent’s workspace and provide the inputs and tools it may use.

environment/

Example

1input/

stations.csv
historical_surge.csv
weather_forecasts.csv
forecast_windows.csv
1

Give the agent the forecast inputs

The files describe the 24 stations, their past observations, the weather forecasts and the issue times. Document units and access terms if data come from elsewhere. Place any agent-facing tools in tools/.

2Dockerfile

FROM python:3.11.11-slim-bookworm
WORKDIR /work
COPY input/ /work/input/
RUN mkdir -p /work/output
2

Make the documented paths exist

COPY makes the input files visible at /work/input/. Install any additional packages here and copy in any tools the agent needs. Held-out observations stay in the independent scoring image.

04 / 05Build an independent verifier and score the submitted artifacts.

tests/

Example

1Dockerfile

FROM python:3.11.11-slim-bookworm
WORKDIR /tests
COPY . /tests/
RUN chmod +x /tests/test.sh
1

Package the evidence for final scoring

Include score.py, the held-out observations and a reference forecast produced for the same windows and input conditions. Join forecasts and observations by station, window and lead hour before comparing errors.

2test.sh

#!/bin/sh
set -eu
mkdir -p /logs/verifier
python3 /tests/score.py
2

Use the Harbor scoring entry point

Harbor calls tests/test.sh. Here score.py reads /work/output/forecast.csv, checks its rows and computes RMSE within each region. It awards 50 points for each region whose RMSE is strictly lower than the reference.

3/logs/verifier/afe_result.json

{
  "status": "evaluated",
  "score": 50,
  "raw": {"regions_improved": 1, "regions_total": 2}
}
3

Record the scientific result

This example output improves in one of two regions. Report status and score, with optional raw metrics in their own units. An evaluated score is between 0 and 100. A task that supports target_exceeded may flag a verified improvement beyond its target at 100.

4/logs/verifier/reward.json

{"reward": 0}
4

Report whether the full goal was met

The 50-point result gets reward 0. An evaluated score of 100 gets 1. For invalid_submission, set score and reward to 0 and include an error. For evaluation_error or pending_review, use a null score and omit the reward file.

05 / 05Optional reference methods, one directory per method.

solution/

Example

1gtsm/info.json

{
  "name": "Global Tide and Surge Model v3.0",
  "proposed_at": "2020",
  "description": "Hydrodynamic model of tides and storm surge.",
  "source_urls": ["https://doi.org/10.3389/fmars.2020.00263"]

1

Document a reference method

If you provide a method, record its name, date, principle and source. This paper describes GTSM v3.0. Add raw metrics or a score only if you measured them under this task’s conditions.

Muis et al. (2020) ↗

2task.toml → [metadata.afe]

reference_urls = ["solution/gtsm/info.json"]
2

Register the reference in the package

Point reference_urls to each method’s folder or info.json. An open challenge can omit solution/ entirely. Keep any comparison data needed to verify the scientific claim in tests/.
